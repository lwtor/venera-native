# ADR-0013：GitHub 私有仓库选择性备份

- 状态：Accepted（实现中）
- 日期：2026-10-09

## 背景

应用数据保存在 Android 应用私有目录及 Room 中；卸载应用会丢失这些数据。项目没有自建服务端，用户希望用自己的 GitHub 账号保存少量结构化数据，并在重装/换机后恢复。用户确认下载媒体不需要云备份，且希望自行选择保存的类别。

## 决策

1. 备份目标是用户账号下的 Private GitHub 仓库，不搭建项目自有服务器。
2. 使用 GitHub App Device Flow，而不是要求用户生成并粘贴可长期使用的 Personal Access Token；申请仓库创建和内容读写的最小必要权限。
3. 在 Android 设备上按用户选择从 Room 导出版本化 DTO；首批类别为收藏/收藏夹、阅读历史/进度和轻量页面偏好。
4. 上传前对数据压缩并用用户提供的备份密码作客户端加密；上传的仓库不保存解密密码或加密密钥。
5. 不备份漫画下载文件、封面/图片缓存或来源 Cookie、Token 等登录凭据。
6. 首版提供手动备份/恢复和按类别合并/替换；自动备份与历史保留策略后续实现，不提供实时双向同步。

## 理由

- Device Flow 适合原生设备，避免将客户端密钥或用户 PAT 固化在应用中；GitHub App 权限比 OAuth App 的账户级 `repo` 范围更细。
- 选择性逻辑快照不绑定 Room 文件布局，便于跨版本迁移，也避免复制 WAL 数据库或本机路径。
- 客户端加密降低 Private 仓库被意外暴露时的个人阅读数据泄露风险；加密密码遗失时，备份无法恢复，必须在 UI 和格式说明中明确告知。
- 排除大媒体文件避免将 GitHub 仓库/LFS 当作通用对象存储，也避免备份用户不要求保留的漫画内容。

## 后果

- 需要注册项目自己的 GitHub App，并将公开 Client ID 配置进原生客户端；App 发布者必须维护权限说明与授权撤销流程。
- 需要版本化备份格式、可靠密码恢复 UX、冲突检测、配额/频率处理以及 Room 事务恢复。
- Git commit 历史会保留此前快照对象；实现必须控制自动备份频率和历史增长，删除“当前快照文件”不能被描述为擦除了所有历史副本。
- 更换 GitHub 提供方时仍可复用同一选择性快照与加密格式。

## 替代方案

- WebDAV：不要求 GitHub 账号，但用户必须自行找到并配置服务器；本需求已明确优先使用 GitHub。
- OAuth App `repo` scope：接入简单，但授权范围可覆盖用户全部私有仓库，权限过宽。
- 只做 Android Auto Backup/SAF 文件导出：不能满足用户指定的 GitHub 在线私有存储目标。
