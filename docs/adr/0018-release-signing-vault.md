# ADR-0018：Release 签名备份与强制证书检查

状态：Accepted（用户于 2026-11-23 指定新密钥与私有库方案）

## 背景

不同电脑上的本地 Release keystore 曾属于不同证书，发布流程没有自动比较指纹，导致新 APK 无法覆盖部分旧版本。用户要求创建新的项目签名密钥，跨电脑恢复，避免公开项目泄露密钥。

## 决定

- 使用独立生成的新 Release 密钥；原有密钥和配置不覆盖。新签名身份不能直接覆盖以旧证书签名的安装，不能依靠递增版本号解决。
- 新 keystore 和本地签名配置打包后以 GnuPG AES256 对称加密，存于私有库 `lwtor/private-vault`。应用户明确要求，随机恢复密码以明文保存在该私有库；可读该库者均可解密，因此私有库访问权限是主要保护边界。必须限制访问并配置 GitHub 双重验证与独立备份。
- 公开项目只记录证书 SHA-256 指纹，不存私钥、密码或加密备份。跨平台恢复由 `tools/restore-signing-vault.py` 提供，拒绝覆盖不一致的现有文件。
- `:app:preReleaseBuild` 校验 keystore 对应证书与项目指纹；`:app:assembleRelease` 完成后验证最终 APK 签名及证书。缺失、错误或不匹配均使构建失败。不得通过修改指纹绕过验证。
- 凭据属于本地配置，Release 构建文档要求关闭 Gradle configuration cache；恢复后的文件均受 Git 忽略规则保护。

## 边界与恢复

私有库并非独立于 GitHub 账号的备份；账号丢失、仓库被删除、密码泄露或已授权设备被入侵均可能造成无法恢复或密钥泄露。须为密钥和密码保留独立安全备份并验证可恢复性。新密钥并不能恢复任何旧证书的覆盖升级能力。具体操作见 `docs/release.md`。
